Original Prompt to recreate

------

I want a clickable, low-fidelity wireframe of a web application. Show it as an interactive HTML prototype so I can click between pages.

**About the app**
- Name: [App name]
- Purpose: [One or two sentences on what the app does and the problem it solves]
- Platform: [Desktop web / mobile / both]

**User types**
Each user type should see its own navigation and only the pages it has access to. Add a role switcher at the top so I can toggle between them.
1. [User type 1, e.g. Admin]: [what they do, e.g. manages users, settings, billing]
2. [User type 2, e.g. Manager]: [what they do, e.g. reviews team activity, approves requests]
3. [User type 3, e.g. Standard user]: [what they do, e.g. submits requests, views their own data]

**Pages**
For each page, list its key sections, components, and actions, and note which user types can see it.
- [Page 1, e.g. Login / Sign up]: all users
- [Page 2, e.g. Dashboard]: all users, but the content differs by role
- [Page 3, e.g. User management]: Admin only
- [Page 4, e.g. Requests / Approvals]: Manager and Admin
- [Page 5, e.g. Settings / Profile]: all users
- [Add more as needed]

**Key flows to show**
- [Flow 1, e.g. A standard user submits a request, then a manager approves it]
- [Flow 2, e.g. An admin invites a new user and assigns a role]

**Style**
- Low fidelity: grayscale, simple boxes, placeholder text and images, no branding
- Label every element clearly (e.g. "Search bar", "Primary CTA", "Data table")
- Put a short annotation on each page explaining what it's for and what differs by role

**Also include**
- A sitemap or page-flow diagram showing how the pages connect
- A permissions matrix (pages × user types) showing who can view and edit what

Before you build, ask me any clarifying questions if something important is missing.
